■ 必須条件
- CDS と annotation を優先し、標準 CRUD で足りる処理を独自 READ で置換しない。
- 業務チェック・認可は UI だけでなく CAP JavaScript 側でも実装する。
- action は CDS 定義と this.on で実装し、更新は cds.tx(req) のトランザクションで行う。
- Destination・環境変数を利用し、認証情報をコード・ログに書かない。
- 実装、変更ファイル一覧、テスト結果、未確定事項を報告する。

■ 受入条件
- 指定ロールで想定どおり表示・登録・変更・action 実行ができる。
- 不正入力、認可不足、外部連携失敗を利用者向けメッセージで処理する。
- 親子の合計・状態・整合性が保存時に保証される。
