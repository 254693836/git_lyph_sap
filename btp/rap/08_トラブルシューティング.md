# トラブルシューティング

## 基本の切り分け順序

1. CDS、BDEF、Behavior Implementation、Service Definition／Bindingがすべて有効化されているか確認します。
2. ADTのProblemsビューで最初のエラーから解消します。
3. ODataサービスのメタデータとFiori Elements Previewを確認します。
4. エラー内容に応じて、CDS・Behavior・サービス・UIのどの層かを切り分けます。

## よくある問題

| 症状 | 主な原因 | 確認・対処 |
| --- | --- | --- |
| Behaviorが有効化できない | CDSのキー、エイリアス、関連定義の不整合 | Interface CDSとBDEFのエンティティ名・キー・Associationを確認 |
| Create／Updateが表示されない | Projection Behaviorに`use create`／`use update`がない | Projection Behaviorの公開操作を確認 |
| Actionが画面に表示されない | Action未公開、UIアノテーション未設定 | Projection Behaviorと`@UI.lineItem`等を確認 |
| 保存時にエラーになる | Validationの`failed`、必須項目不足 | OData応答のメッセージと対象項目を確認 |
| Draft編集できない | Draft設定、Draftテーブル、ETag／Lockの不足 | BDEFの`with draft`、テーブル、アクション定義を確認 |
| Fiori画面に項目が出ない | UIアノテーション未設定、キャッシュ | ProjectionまたはMetadata Extensionを確認し、再読込 |
| ODataサービスを開けない | Service Binding未Publish | BindingをPublishし、Service URLを確認 |

## 代表的な確認場所

| 確認対象 | 確認方法 |
| --- | --- |
| コンパイル／有効化エラー | ADTのProblemsビュー |
| Behavior実装のデバッグ | ABAP Debugger、ブレークポイント |
| ODataメタデータ | Service BindingのサービスURLで`$metadata` |
| Fiori UI | Fiori Elements Preview、ブラウザ開発者ツール |
| メッセージ | ODataレスポンス、Fioriのメッセージポップオーバー |

## 再発防止

- 開発オブジェクトは依存関係の下位（CDS）から順番に有効化します。
- BehaviorとProjection Behaviorの公開範囲をレビューします。
- Validationには正常系・異常系のテストケースを用意します。
- 実装例は、サービス公開・Fioriプレビューまでを一連で確認します。
