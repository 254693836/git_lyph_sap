# SAP FI認定試験対策・実機演習（SAP S/4HANA On-Premise / Private Cloud）

> **自主学習用のオリジナル演習です。SAP公式の試験問題や採点方式ではありません。** 既存の[FI練習問題500問](README.md)と組み合わせ、知識をSAP GUIでの設定確認・転記・消込・結果検証に結び付けます。

- **対象**：SAP S/4HANA On-Premise / Private Cloud、SAP GUIを利用できる学習者
- **構成**：10課題 × 10点＝100点（自主目標90点）
- **目安**：全体で3〜5時間（環境準備・トラブル対応を除く）。1日1課題でも可
- **対応する英語版**：[SAP FI Hands-on Practice — 10 Exercises](15_FI_Hands_on_Practice_10_Exercises_EN.md)
- **注意**：T-codeや画面はリリース、権限、顧客設定によって異なる。操作可能な範囲で実施する

## 実施前の安全確認

1. **検証用クライアント／会社コード**を使用する。本番環境ではマスタ変更、カスタマイズ変更、転記、支払実行をしない。
2. 既存の会社コード、G/L勘定、テスト用BP、銀行関連勘定、転記可能な会計期間を確認する。ここに示す金額・コードは演習例であり、実環境の設定を優先する。
3. `OB52`、`FBZP`、`OB08`、`OBA7`などは、まず**表示・確認のみ**。変更が必要なら権限と承認を得た検証環境で実施する。
4. `F110`は**支払提案の確認まで**を基本とする。実際の支払実行、支払媒体の銀行送信は行わない。
5. 画面共有・GitHubへの記録には、実在の取引先名、口座番号、機密情報を含めない。

## 課題1：FI組織・基本設定（10点）

**目的**：会社コードが会計伝票を転記できる状態か、組織設定・転記期間・伝票タイプの観点から判断する。**この課題では保存や転記を行わない。**

### ステップ1-1：OBY6 — 会社コード基本設定（3点）

1. SAP GUIのコマンド欄で`/nOBY6`を実行する。
2. 演習対象の会社コードを選択し、詳細を表示する。
3. 次の6項目を記録する。

| 項目 | 確認内容 | 記入欄 |
|---|---|---|
| Company Code | 4桁の会社コード | __________ |
| Chart of Accounts | 勘定コード表 | __________ |
| Currency | 会社コード通貨 | __________ |
| Fiscal Year Variant | 会計年度バリアント | __________ |
| Posting Period Variant | 転記期間バリアント | __________ |
| Field Status Variant | 項目ステータスバリアント | __________ |

**理解確認**：勘定コード表は使用できるG/L勘定体系、会計年度バリアントは期間構成、転記期間バリアントは転記可否、項目ステータスバリアントは入力項目の制御に関係することを説明する。標準の`K4`は通常1〜12期間と特別13〜16期間を持つ暦年ベースのバリアント。

**採点**：基本設定の確認1点／会計年度・転記期間の確認1点／設定の役割を説明1点。

### ステップ1-2：OB52 — 転記期間（3点）

1. `/nOB52`を実行し、OBY6で確認した**転記期間バリアント**を探す。
2. 勘定タイプ`+`（全タイプ）および`S`（G/L）の行を確認する。必要に応じて`D`（得意先）、`K`（仕入先）、`A`（資産）、`M`（品目）も確認する。
3. 勘定範囲、**第1・第2の期間範囲**（From/To Period・Year）、権限グループの有無を記録する。第2範囲が常に特別期間専用というわけではない。
4. **2026年11月のG/L伝票**が期間設定上転記可能か判断する。会計年度バリアントが`K4`以外なら対象の会計期間を先に特定する。

| 記録項目 | 記入欄 |
|---|---|
| 対象転記期間バリアント | __________ |
| `+` の期間・年度（第1／第2範囲） | __________ |
| `S` の期間・年度（第1／第2範囲。行がなければその旨） | __________ |
| 対象G/L勘定の勘定範囲・権限条件 | __________ |
| 2026年11月のG/L転記可否と理由 | __________ |

**判断のポイント**：`+`だけでなく対象勘定タイプ・勘定範囲・権限等の条件を確認する。期間が開いていても、他のマスタ設定や伝票エラーにより転記できない場合がある。

**採点**：バリアント確認1点／期間範囲と勘定タイプの理解1点／転記可否の根拠1点。

### ステップ1-3：OBA7 — 伝票タイプSA（4点）

1. `/nOBA7`を実行し、伝票タイプ`SA`（一般的なG/L転記用）を表示する。
2. **説明、番号範囲、許可勘定タイプ、番号採番関連設定**を確認する。
3. 番号範囲の実体は必要に応じて`FBN1`で**表示のみ**確認する（会社コード・年度に注意）。
4. 「SAでG/L勘定への借方・貸方を転記できるか」「番号範囲が設定されていないと何が起きるか」を説明する。

| 記録項目 | 記入欄 |
|---|---|
| 伝票タイプ | SA |
| 説明 | __________ |
| 番号範囲キー／設定状況 | __________ |
| 許可勘定タイプ | __________ |
| 想定される転記可否・エラー | __________ |

**採点**：SAの特定1点／番号範囲の確認1点／許可勘定タイプの確認1点／設定と転記の関係の説明1点。

**課題1の提出物**：OBY6・OB52・OBA7の確認表、2026年11月の転記可否の判断と理由（機密情報は除外）。

## 課題2：G/L勘定と会計伝票（10点）

**要求**：検証用会社コードで**費用30,000円／未払費用30,000円**を計上する。

1. `FS00`で費用勘定と未払費用勘定の存在・会社コード拡張・転記可否を確認する。
2. `FB50`で転記日付、伝票日付、会社コード、通貨`JPY`を指定し、次の仕訳を入力する。
3. 費用勘定が原価センタを必要とする場合は、適切なテスト用原価センタを入力する。
4. シミュレーションで借貸一致を確認し、検証環境で転記する。`FB03`やG/L明細で結果を確認する。

| 借方 | 貸方 |
|---|---|
| 費用勘定 30,000円 | 未払費用勘定 30,000円 |

**合格条件**：転記済み伝票番号があり、借貸30,000円ずつ、G/L明細が一致する。**証跡**：伝票番号・転記日付・勘定・金額。

## 課題3：仕入先請求書（10点）

**要求**：テスト仕入先から**税なし100,000円**の請求書を登録する。

1. `BP`で`FLVN00`（FI仕入先）ロール、会社コードデータ、統制勘定、支払条件を確認する。
2. `FB60`でテスト仕入先、会社コード、日付、通貨、費用勘定、100,000円を入力する。**税なしの例**として処理し、実環境の税設定に従う。
3. 転記後、`FBL1N`で未消込明細と支払期日を確認する。

| 借方 | 貸方 |
|---|---|
| 費用 100,000円 | 仕入先 100,000円 |

**合格条件**：仕入先の未消込明細に100,000円が表示される。**証跡**：請求書伝票番号、仕入先、期日、未消込状態。

## 課題4：仕入先支払と消込（10点）

**要求**：課題3の請求書100,000円を支払処理し、消込結果を確認する。

1. `F-53`で支払日付、会社コード、支払金額、**検証用銀行仮勘定等**を指定する。
2. 課題3の仕入先未消込明細を選択し、金額差異がないことを確認する。
3. 検証環境で転記し、`FBL1N`で請求書と支払の消込状況を確認する。

| 借方 | 貸方 |
|---|---|
| 仕入先 100,000円 | 銀行関連勘定 100,000円 |

**合格条件**：対象請求書が消込済みとなり、消込伝票番号が確認できる。**注意**：SAPでの支払転記と実際の銀行送金は別。実銀行への送金は行わない。

## 課題5：得意先請求書と入金消込（10点）

**要求**：テスト得意先へ**税なし80,000円**を請求し、同額の入金を消し込む。

1. `BP`で`FLCU00`（FI得意先）ロール、会社コードデータ、統制勘定を確認する。
2. `FB70`で得意先請求書80,000円を転記する。仕訳：**借方 得意先80,000円／貸方 売上80,000円**。
3. `F-28`で入金80,000円を転記し、対象請求書を選択して消し込む。仕訳：**借方 銀行関連勘定80,000円／貸方 得意先80,000円**。
4. `FBL5N`で未消込→消込済みへの変化を確認する。

**合格条件**：請求書と入金の伝票・消込情報が追跡できる。

## 課題6：F110自動支払（10点）

**要求**：テスト仕入先の請求書について、**支払提案まで**実行する。

1. `FBZP`で支払方法（国・会社コード）、銀行決定、支払会社コード等を**表示・確認**する。
2. 支払期日が到来したテスト用未払請求書を用意し、支払保留の有無、BPの支払方法・銀行情報を確認する。
3. `F110`で実行日・識別子を指定し、パラメータ（会社コード、支払方法、転記日付、次回支払日、仕入先選択範囲等）を入力する。
4. **支払提案**を作成し、対象明細・例外ログ・除外理由を確認する。**支払実行と銀行送信はしない。**

**合格条件**：支払対象と除外対象の理由を、期日・支払保留・支払方法・銀行設定から説明できる。**証跡**：実行日・識別子・提案ログ（機密情報を除外）。

## 課題7：固定資産会計（10点）

**要求**：テスト資産を**取得価額600,000円、耐用年数5年、残存価額0円、定額法**で登録する。

1. `AS01`で検証用の資産クラス、会社コード、原価センタ等を指定して資産マスタを作成する。
2. 償却領域、償却キー、耐用年数、償却開始日を確認する。
3. `F-90`でテスト仕入先から資産600,000円を取得する（環境の資産取得プロセスに従う）。
4. `AW01N`で取得価額、予定償却、資産価額を確認し、G/L転記と照合する。

**計算上の年間定額償却**：600,000 ÷ 5 ＝ **120,000円**。実際の期間別償却は償却キー、期間制御、取得日等に依存する。

**合格条件**：取得価額と会計転記が一致し、償却予定を説明できる。**注意**：`AFAB`による実際の償却転記は、承認された検証環境のみ。

## 課題8：外貨会計（10点）

**要求**：USD建て売掛金の決済差額を計算し、外貨評価の設定と区別する。

| 項目 | 条件 |
|---|---|
| 請求額 | USD 100 |
| 請求時レート | 1 USD = 150円 |
| 決済時レート | 1 USD = 148円 |
| 請求時円換算額 | 15,000円 |
| 決済時円換算額 | 14,800円 |
| 差額 | **200円の為替差損（売掛金の例）** |

1. `OB08`で通貨ペア、換算レートタイプ、有効日を確認する（**変更しない**）。
2. 上表の実現為替差損200円を計算し、理由を説明する。
3. `FAGL_FCV`が利用可能なら、**未消込外貨明細の期末評価**について評価基準日・評価方法・元帳を確認し、テスト／シミュレーションで結果を確認する。
4. **決済による実現差損益**と、**期末評価による未実現差損益**を区別する。

**合格条件**：200円の差損を計算し、評価日・レート・元帳の違いを説明できる。例示レートはシステム登録値と一致するとは限らない。

## 課題9：決算と残高照合（10点）

**要求**：対象会社コード・期間・元帳・通貨をそろえ、以下を照合する。

1. `FBL1N`の仕入先明細と買掛金統制勘定残高。
2. `FBL5N`の得意先明細と売掛金統制勘定残高。
3. `AW01N`等の資産台帳と固定資産G/L残高。
4. `F.01`の財務諸表と`FAGLL03H`等のG/L明細（環境に応じた利用可能なレポート）。

**合格条件**：差異の有無と原因候補を説明できる。未消込残高と勘定全体残高を比較する際は、**比較対象・基準日・消込状態・対象勘定**を一致させること。**証跡**：選択条件、各残高、差異、調査結果。

## 課題10：FI障害対応（10点）

**要求**：以下の3ケースについて、**エラー内容 → 原因候補 → 確認場所 → 修正案 → 再テスト**を記述する。

| ケース | 主な確認箇所 | 再テストの例 |
|---|---|---|
| 転記期間が閉じている | OB52、転記日付、期間バリアント | 許可された期間での転記シミュレーション |
| 仕入先請求書を登録できない | BP会社コードデータ、統制勘定、項目制御 | FB60で入力・シミュレーション |
| F110提案に請求書が表示されない | 支払期日、支払保留、支払方法、選択条件、例外ログ | 同一条件で提案を再作成しログ確認 |

**合格条件**：少なくとも各ケースについて根拠のある原因候補、確認手順、再テスト条件を示す。設定変更は必要な承認がある検証環境のみ。

## 推奨学習順序

1. 500問の関連範囲を20分復習する。
2. その日の実機課題を40分操作し、結果を記録する。
3. 失敗した操作は、エラーメッセージ・設定・転記結果を整理して再挑戦する。
4. 最後に**設定 → 転記 → 消込 → 残高照合**の一連の流れを自力で説明する。
